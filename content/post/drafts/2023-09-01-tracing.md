Après des années à éluder le sujet par manque de temps, il est grand temps que je me penche sur le (Distributed)Tracing.

A vrai dire, j'ai déjà un peu joué avec au cours des dernières années, mais jamais vraiment pris le temps de m'y pencher sérieusement.

Pourtant, le tracing est quelque chose qui est déjà bien ancré dans les outils "cloud native" depuis un bon moment. Ici, on va directement mettre les mains dans le cambouis avec un exemple "clé en main".

En préambule de cet article, je vous incite à aller lire l'article de Mathieu Corbin : [Tracing avec Opentelemetry: pourquoi c'est le futur (et pourquoi ça remplacera les logs)](https://www.mcorbin.fr/posts/2023-08-20-traces/) pour mieux comprendre de quoi il s'agit.





## L'application en elle même

On va commencer simple et juste déployer l'application.

Comme j'aime le recyclage, je vais réutiliser une application triviale en python que j'avais écrit pour un talk sur Ansible : button clicker. Pour faire simple, c'est une application Flask en python qui écrit en base (postgreSQL) à chaque fois qu'on clique sur un bouton et une page HTML qui affiche le nombre de fois qu'on a cliqué.

[Le code ainsi que la chart helm sont disponibles à l'adresse github.com/zwindler/button-clicker](https://github.com/zwindler/button-clicker).

On déploie l'application sur notre cluster kubernetes (n'hésitez pas à changer les *values* via `helm/values.yaml`, notamment ingress.host) :

```bash
git clone https://github.com/zwindler/button-clicker && cd button-clicker
helm install buttonclicker helm/
```

Au bout de quelques secondes, l'application démarre (c'est très léger) et on peut commencer à comptabiliser les "clics" en base de données. C'est chouette d'avoir une app, mais ça serait mieux si on pouvait avoir quelques métriques/logs dessus.
